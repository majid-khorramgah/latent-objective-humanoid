# Latent Objective Humanoid

**Repository:** [latent-objective-humanoid](https://github.com/majid-khorramgah/latent-objective-humanoid)

This project investigates a latent-objective framework for human motion processing and learning, with a focus on transforming motion-capture data into structured representations suitable for downstream latent-space learning and humanoid motion modeling.

# AMASS Dataset Processing

The project uses the **AMASS** motion-capture collection as the primary source of human motion data.

The raw AMASS files are intentionally **not stored in this GitHub repository** because the dataset is large and is distributed separately.

The processing pipeline operates on valid AMASS motion sequences and reconstructs them using the **SMPL-X** body model.

The overall transformation is:

~~~text
AMASS raw motion
       |
       v
AMASS SMPL+H 156-D pose representation
       |
       v
Explicit pose mapping
       |
       v
SMPL-X body model
       |
       v
3D human body joints
       |
       v
Processed SMPL-X motion representation
~~~

---

# Stage 03 — SMPL-X Reconstruction

Stage 03 reconstructs valid AMASS motion sequences using the available SMPL-X body models.

The reconstruction script is:

[02_smplx_reconstruction.py](https://github.com/majid-khorramgah/latent-objective-humanoid/blob/main/04_latent_objective_learning/03_human_data/scripts/02_smplx_reconstruction.py)

The source AMASS representation used by this stage is:

~~~text
AMASS SMPL+H-style pose
156 dimensions
~~~

with the following structure:

~~~text
3    global orientation
63   body pose
45   left hand pose
45   right hand pose
--------------------
156 total
~~~

The target representation is SMPL-X.

For each valid sequence, the AMASS pose parameters are mapped explicitly to SMPL-X inputs. Facial parameters such as jaw, eye poses, and expression are initialized to zero because they are not represented in the AMASS 156-D pose vector used by this pipeline.

---

# Reconstruction Output

The reconstruction produces 3D joint coordinates from the SMPL-X body model.

The primary output is:

~~~text
joints
~~~

with a typical shape of:

~~~text
(N, 127, 3)
~~~

where:

- `N` = number of motion frames
- `127` = SMPL-X joints / landmarks returned by the model
- `3` = XYZ coordinates

For example:

~~~text
360 frames
x
127 joints
x
3 coordinates
~~~

The processed files preserve the original AMASS directory hierarchy so that every reconstructed sequence can be traced back to its source sequence.

# SMPL-X Joint Structure

The complete 127-joint structure generated by Stage 03 is documented in:

[smplx_joint_structure.json](https://github.com/majid-khorramgah/latent-objective-humanoid/blob/main/04_latent_objective_learning/03_human_data/results/statistics/smplx_joint_structure.json)

This file defines the joint schema used by the processed human-motion representation and provides the canonical mapping between joint indices, joint names, anatomical groups, and future ablation configurations.

The current schema is:

~~~text
Schema version: stage03-joint-extraction-v1
Model: SMPL-X
Total joints: 127
~~~

The 127 joints are constructed from:

| Source component | Count | Description |
|---|---:|---|
| SMPL-X regressed joints | 55 | Standard SMPL-X body and articulated joint outputs |
| Vertex-selector extra joints | 21 | Additional anatomical points selected from SMPL-X vertices |
| Facial landmarks | 51 | Facial landmarks used to preserve the full facial representation |
| **Total** | **127** | Complete processed joint representation |

The resulting representation therefore combines the main articulated body skeleton with contact points, hand landmarks, and facial landmarks.

---

## Joint Partition

The 127 joints are also divided into four functional groups:

| Group | Count | Purpose |
|---|---:|---|
| `body_core` | 22 | Primary whole-body motion skeleton |
| `body_contact` | 6 | Foot and ground-contact related points |
| `hands` | 40 | Finger joints and fingertips |
| `face` | 59 | Facial joints and facial landmarks |
| **Total** | **127** | Complete joint representation |

This partition is important because the complete 127-joint representation is preserved in the dataset, while different subsets can later be selected for different learning objectives.

## Body Contact — 6 Joints

The `body_contact` group contains toe and heel points that are particularly useful for contact detection, locomotion analysis, and future humanoid motion objectives.

The six joints are:

~~~text

61  left_small_toe
62  left_heel
63  right_big_toe
64  right_small_toe
65  right_heel
~~~

These points are intentionally preserved separately from the main 22-joint body skeleton so that contact-related objectives can be modeled explicitly.

The articulated finger joints are represented by the corresponding `1`, `2`, and `3` joint levels, followed by fingertip locations.

The hand indices are:

The hand representation is preserved for future manipulation, dexterous motion, and hand-object interaction objectives.

25 ... 54

Additional facial / anatomical joints:

# Default and Extended Representations

The joint structure is designed to support multiple representations without changing the underlying processed data.

The default representation is:

~~~text
body_core
22 joints
~~~

This provides the primary whole-body motion skeleton.

Additional subsets can be enabled for specialized objectives.

For example:

~~~text
body_core
+
body_contact
~~~

provides a representation suitable for locomotion and contact-aware motion learning.

Similarly:

~~~text
body_core
+
hands
~~~

provides a representation suitable for whole-body motion together with hand articulation.

A larger representation can combine:

~~~text
body_core
+
body_contact
+
hands
~~~

while the full processed representation retains all:

~~~text
127 joints
~~~

including the facial landmarks.

These configurations allow future experiments to compare different motion representations without regenerating the underlying SMPL-X reconstruction.

---

# Joint-Structure Ablation Options

The `smplx_joint_structure.json` file also defines predefined joint subsets for future ablation experiments.

The available configurations include:

~~~text
core_only
core_plus_contact
core_plus_hands
core_plus_contact_plus_hands
full_body_127
~~~

Their intended interpretation is:

| Configuration | Purpose |
|---|---|
| `core_only` | Primary 22-joint whole-body representation |
| `core_plus_contact` | Whole-body motion plus foot/toe/heel contact information |
| `core_plus_hands` | Whole-body motion plus articulated hand information |
| `core_plus_contact_plus_hands` | Whole-body motion with contact and hand information |
| `full_body_127` | Complete processed 127-joint representation |

The exact indices for each configuration are stored directly in:

[smplx_joint_structure.json](https://github.com/majid-khorramgah/latent-objective-humanoid/blob/main/04_latent_objective_learning/03_human_data/results/statistics/smplx_joint_structure.json)

This makes the representation selection explicit and reproducible for downstream experiments.

---

# Why the 127-Joint Structure Is Preserved

The pipeline intentionally preserves the complete 127-joint representation rather than immediately reducing the data to a small body skeleton.

This provides several advantages:

- The main body skeleton remains available for general motion learning.
- Foot contact points remain available for locomotion objectives.
- Hand articulation remains available for manipulation-related objectives.
- Facial information remains available for future experiments.
- Different joint subsets can be evaluated without reconstructing the original AMASS data.
- Representation ablations can be performed consistently across experiments.
- The exact joint ordering remains fixed across the processed dataset.

Therefore, the 127-joint representation acts as a common intermediate representation from which smaller task-specific representations can be derived.

# GRAB Dataset Status

The current reconstruction pass did not reconstruct the GRAB sequences.

All 1,340 failed sequences belong to GRAB.

The current loader expects the field:

~~~text
mocap_framerate
~~~

However, the available GRAB files do not contain this field.

Therefore, GRAB sequences are currently excluded from the SMPL-X reconstruction result rather than assigning an assumed frame rate.

This is treated as a dataset-schema compatibility issue and is kept separate from the successful reconstruction of the other AMASS subsets.

# Reproducibility

The reconstruction pipeline supports:

- CPU execution
- CUDA execution
- Configurable batch size
- Deterministic sequence sampling
- Dataset filtering
- Optional vertex reconstruction
- Output validation
- Per-sequence failure reporting
- Preservation of source dataset hierarchy
- Explicit joint-index and joint-name mapping
- Reproducible joint-subset selection

A CUDA reconstruction can be run with:

~~~text
python 04_latent_objective_learning/03_human_data/scripts/02_smplx_reconstruction.py --batch-size 1024 --device cuda --overwrite
~~~

The exact command should be adjusted according to the local project structure and available GPU memory.
