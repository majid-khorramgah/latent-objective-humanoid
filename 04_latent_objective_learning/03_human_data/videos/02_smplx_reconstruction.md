# 02 — SMPL-X Reconstruction

## Overview

This stage reconstructs valid AMASS motion sequences using the SMPL-X body model.

The purpose of this stage is to convert the original AMASS pose representation into explicit 3D human body joint coordinates generated by SMPL-X.

The processing pipeline is:

AMASS SMPL+H 156-D
→ explicit pose mapping
→ SMPL-X
→ 3D human joints

This stage does not modify the original AMASS files.

---

## Input

The input consists of valid AMASS motion sequences identified by the inventory generated during the previous data-processing stage.

The original AMASS files contain information such as:

- pose parameters
- global translation
- body shape coefficients
- gender
- motion capture frame rate

The source pose representation used by this stage is the AMASS SMPL+H-style 156-dimensional representation:

- 3 dimensions — global orientation
- 63 dimensions — body pose
- 45 dimensions — left hand
- 45 dimensions — right hand

Total:

156 pose parameters per frame.

---

## SMPL-X Mapping

The available body models in the project are SMPL-X models.

The AMASS 156-dimensional pose representation is explicitly mapped to the SMPL-X input representation.

The mapping is:

- `poses[:, 0:3]` → `global_orient`
- `poses[:, 3:66]` → `body_pose`
- `poses[:, 66:111]` → `left_hand_pose`
- `poses[:, 111:156]` → `right_hand_pose`

AMASS does not provide the facial parameters required by SMPL-X in this 156-dimensional pose representation.

Therefore the following parameters are initialized to zero:

- `jaw_pose`
- `leye_pose`
- `reye_pose`
- `expression`

The body shape coefficients are expanded across all frames of each sequence.

---

## Reconstruction

For each valid AMASS sequence, the pipeline:

1. Resolves the original AMASS file path.
2. Loads the motion sequence.
3. Validates the pose and translation dimensions.
4. Determines the subject gender.
5. Loads the corresponding SMPL-X model.
6. Maps the AMASS SMPL+H pose representation to SMPL-X.
7. Expands the body shape coefficients across frames.
8. Runs the SMPL-X forward pass.
9. Extracts 3D human joints.
10. Validates the reconstructed values.
11. Saves the reconstructed sequence.

The original AMASS files remain unchanged.

---

## GPU Processing

The reconstruction can run on CPU or CUDA.

For the full reconstruction run, CUDA acceleration was used with an NVIDIA RTX 3090.

The production run used:

- Device: CUDA
- GPU: NVIDIA GeForce RTX 3090
- Batch size: 1024
- SMPL-X model: SMPL-X
- Vertices: disabled

Batch processing is used to significantly reduce reconstruction time compared with processing individual frames.

The final partial batch is safely padded before the SMPL-X forward pass and the artificial frames are removed from the output.

## Output

The reconstructed sequences are stored under:

`03_human_motion/data/processed/smplx/`

The original AMASS directory hierarchy is preserved.

For example:

`03_human_motion/data/AMASS/raw/ACCAD/Female1General_c3d/A1 - Stand_poses.npz`

becomes:

`03_human_motion/data/processed/smplx/ACCAD/Female1General_c3d/A1 - Stand_poses.npz`

The processed file contains the reconstructed 3D joint coordinates and reconstruction metadata.

The main reconstructed array is:

`joints`

with the shape:

`(N, J, 3)`

where:

- `N` = number of motion frames
- `J` = number of SMPL-X joints
- `3` = X, Y, Z coordinates

In the current reconstruction, the joint output has 127 SMPL-X joints.

---

## Important Difference from AMASS Raw Data

The processed files may look structurally similar to the original AMASS `.npz` files because both use NumPy compressed archives.

However, they represent different stages of the pipeline.

### AMASS raw

The original AMASS files primarily contain motion parameters such as:

- pose parameters
- body shape coefficients
- global translation
- gender
- frame rate

These parameters describe how the human body should be posed.

### SMPL-X processed

The processed files contain:

- reconstructed 3D joints
- reconstruction metadata

The pose parameters have been passed through the SMPL-X body model to obtain explicit 3D body geometry/joint coordinates.

Therefore, the processed dataset is not a duplicate of AMASS. It is a model-derived representation of the motion.

## GRAB Dataset

All 1,340 reconstruction failures belong to the GRAB dataset.

The current reconstruction script expects the AMASS field:

`mocap_framerate`

The affected GRAB files do not contain this field.

Therefore, these sequences were reported as failures and were not included in the reconstructed output.

This is recorded in:

`03_human_motion/results/statistics/reconstruction_failures.csv`

The GRAB sequences were not silently discarded; they were explicitly reported by the reconstruction pipeline.

The large processed motion files themselves are not committed to the Git repository.

---

## Validation

Each reconstructed sequence is validated before being saved.

The validation checks include:

- correct frame count
- correct joint dimensionality
- finite joint coordinates
- absence of NaN values
- absence of infinite values
- valid motion capture frame rate

If vertices are requested, they are also checked for finite values.

## Reproducibility

The reconstruction script is:

`03_human_motion/scripts/02_smplx_reconstruction.py`

A CUDA reconstruction can be launched with:

`python 03_human_motion/scripts/02_smplx_reconstruction.py --batch-size 1024 --device cuda --overwrite`

The command processes the valid sequences selected from the AMASS inventory.

A smaller deterministic test can be performed using:

`--sample N`

A specific dataset can be selected using:

`--dataset DATASET_NAME`

For example:

`--dataset ACCAD`

## Role in the Overall Pipeline

This stage creates the 3D human motion representation required by later stages of the project.

Conceptually:

AMASS raw motion
→ validated motion inventory
→ SMPL-X reconstruction
→ 3D human joints
→ downstream human-motion processing
→ latent objective learning

The main purpose is therefore to transform parameterized AMASS motion into a consistent SMPL-X-based 3D representation suitable for subsequent computational processing and learning.
